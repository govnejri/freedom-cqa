# CQA — как работает и как пользоваться

## 1. Как устроено

1. **Загрузка.** Диалоги приходят из API организаторов по `group_id`. Код размечает их: ID реплик (`m1`, `m2`…), участки (бот → ожидание оператора → оператор → удержание), системные события, паузы, начало и паузы записи. mp3 звонков скачиваются сразу: ссылка организаторов живёт около часа.
2. **Оценка.** По каждому из 8 критериев — один вызов Gemini 3.8 Flash. В вызове правило из чек-листа, наши трактовки спорных мест, примеры «так Да, так Нет» и размеченный диалог. Модель возвращает вердикт, цитаты и обоснование.
3. **Проверка.** Код проверяет, что цитата действительно есть в реплике, что реплика того спикера и что N/A разрешён. Если нет — один повтор с описанием ошибки.
4. **Баллы.** Код считает итог по правилам чек-листа: шкалы пересчитываются в баллы, вес N/A перераспределяется, итог округляется до сотых, грубые ошибки отмечаются отдельно.
5. **Хранение.** У каждой оценки сохраняются версия чек-листа, модель, каждый вызов модели (запрос, ответ, токены, цена) и решения по апелляциям. Повторный прогон без изменений берётся из кэша мгновенно и бесплатно.

Точность на DEV — на уровне согласия двух людей-разметчиков между собой: ошибка итога 2.86 балла против 2.87. Цена — $0.024 за диалог. Подробности — `docs/core-eval.md`.

## 2. Запуск

```bash
uv sync
uv run cqa serve                 # http://127.0.0.1:8000 — интерфейс и API
```

- **При первом старте** сервер сам применяет схему БД, импортирует чек-лист и эталон. Если база пустая, он загружает `data/dev.json`.
- **Демо без сети:** `uv run cqa serve --fake` — детерминированная «модель» вместо Gemini.
- **Только интерфейс на мок-данных:** `uv run cqa ui-preview` → http://127.0.0.1:8090/?mock=1.
- **Ключи** лежат в `.env`: `GEMINI_API_KEY`, `CQA_API_URL` (ссылка из гайда), позже `LOCAL_LLM_BASE_URL`.

## 3. Экраны по ролям

### Руководитель

| Экран | Что показывает | Как пользоваться |
| --- | --- | --- |
| **Сводка** `#/` | счётчики (диалоги, средний балл, грубые ошибки, требуют проверки, апелляции); **радар рисков**; **вопросы без ответа** по темам; **причины обращения** с баллом и долей решённых | клик по цитате в радаре → карточка на нужной реплике. «В комплаенс» передаёт случай. «Посчитать сигналы» — один вызов на диалог, около $0.002 |
| **Риски** `#/risks` | все грубые ошибки: оскорбление, обход компании, раскрытие данных — с цитатами | фильтр по категории, «только не переданные» |
| **Срезы** `#/slices` | средний балл и выполнение каждого критерия по языку, каналу, оператору, причине обращения — тепловая карта | клик по группе → её диалоги |
| **Ассистент** `#/assistant` | вопрос обычным языком → ответ с цифрами и ссылками на диалоги | примеры: «Почему клиенты недовольны выводом средств?», «Сколько грубых ошибок и каких типов?». Ответ — 25–30 с, около $0.02. Видно SQL-запрос и данные |

### QA-специалист и проверяющий

| Экран | Что показывает | Как пользоваться |
| --- | --- | --- |
| **Диалоги** `#/conversations` | все диалоги: язык, канал, оператор, итог, отметки «грубая ошибка», «требует проверки», «апелляция» | фильтры, сортировка по баллу, экспорт CSV/JSON |
| **Карточка** `#/c/{uid}` | слева транскрипт с участками и плеер, справа итог, секции и критерии: вердикт, баллы, вес, обоснование, цитаты, «как надо было» | клик по чипу `m12` → прокрутка к реплике, у звонка плеер перематывается на эту секунду. «Как посчитан итог» — перераспределение весов. «Журнал оценки» — каждый вызов модели. «Оспорить» — у каждого критерия |
| **Журнал** `#/log/{id}` | все вызовы модели по этой оценке: цель, модель, токены, цена, задержка, кэш | клик по строке — полный запрос и сырой ответ модели. Это доказательство, что система реально анализирует |
| **Апелляции** `#/appeals` | открытые и решённые апелляции | открыть → спорная оценка, комментарий оператора, фрагмент диалога. «Запросить второе мнение ИИ» — модель оценивает заново, не видя исходного вердикта. Решение «подтвердить» или «изменить» с причиной → итог пересчитывается, исходная оценка остаётся в истории. Галочка «сделать прецедентом» |
| **Чек-лист** `#/checklists/freedom-cqa` | версии, критерии, общие правила | изменить или добавить критерий (тип, вес, N/A, шкала, трактовки, примеры) → «Сохранить как новую версию» → «Пробный прогон на 10 диалогах» → «было/стало» → «Сделать активной» → «Применить ко всем» |
| **Качество** `#/quality` | точность по каждому критерию против эталона и против потолка (согласие двух разметчиков), ловушки, разрез по языкам, стоимость; сравнение прогонов и моделей; автотесты | выбор прогона и выборки (все / рабочие / отложенные) |

### Оператор

| Экран | Что показывает | Как пользоваться |
| --- | --- | --- |
| **Профиль** `#/operators/{имя}` | балл против отдела, 3 зоны роста с примерами из своих диалогов и «как надо было», сильные стороны | «Сводка от ИИ»; «Потренироваться» у зоны роста. Звонки без имени назначаются вручную на странице операторов |
| **Тренажёр** `#/trainer` | ИИ играет клиента из провального диалога, оператор отвечает заново | «Потренироваться» в карточке или профиле → переписка → «Завершить и оценить» → «было/стало» по тому же чек-листу; показывается, какой второй вопрос клиент хотел задать. Уроки для отдела |
| **Тьютор** `#/tutor` | ответы на «почему мне снизили 04?», «как отвечать про вывод средств?» | ответ ссылается на свои оценки, чек-лист и лучшие ответы коллег (`[S1]` → реплика). Если ответа нет — так и говорит |

### Настройки `#/settings`

- Модель для каждой роли: судья, сильная модель, перекрёстная проверка, сигналы.
- Переключатель **«Облако / Локальная модель»**. Локальная станет доступна, когда в `.env` появится `LOCAL_LLM_BASE_URL`.

Экраны операторов, срезов, тренажёра, тьютора, ассистента и навигация по ролям сейчас дорабатываются. Их бэкенд уже работает — через API и CLI ниже.

## 4. Типовые сценарии

**Оценить новый набор**
- В интерфейсе: «Сводка» → «Загрузить набор» (`group_id`) → «Оценить всё». Прогресс — на экране прогона.
- То же из CLI: `uv run cqa load --group G && uv run cqa eval --group G`.

**Оспорить оценку**
1. В карточке: «Оспорить» у критерия → комментарий → клик по репликам-контрдоказательствам.
2. «Апелляции» → открыть → по желанию «Второе мнение ИИ» → решение с причиной.
3. Итог пересчитан. В карточке видны и исходная оценка, и решение.

**Заменить критерий (контрольный этап)**
1. «Чек-лист» → изменить критерий → сохранить версию.
2. «Пробный прогон» — около 10 диалогов, секунды.
3. «Было/стало» → «Сделать активной» → «Применить ко всем».
4. Пересчитывается только изменённый критерий: на репетиции 10 диалогов заняли 12 с и $0.03.

**Научить оценку на апелляции**
1. Решение по апелляции с галочкой «прецедент».
2. «Создать версию с прецедентом» — пример попадает в критерий.
3. «Проверить на похожих диалогах» → «было/стало» → опубликовать.

**Потренировать оператора**
- Карточка или профиль → «Потренироваться» → 2–3 реплики → «Завершить и оценить».

## 5. CLI

| Задача | Команда |
| --- | --- |
| Загрузить набор | `cqa load --group DEV` · `cqa load --file data/dev.json --group DEV` |
| Посмотреть разметку диалога | `cqa show DEV:p4-ru-002 --segments` |
| Оценить один диалог | `cqa evaluate DEV:p1-ru-022 [--criteria 03,08]` |
| Прогон + метрики на эталоне | `cqa eval --group DEV --gold eval/gold.csv [--split holdout] [--criteria 04,05] [--experiment]` |
| Прогоны | `cqa runs list` · `cqa runs resume ID` · `cqa runs retry-failed ID` |
| Экспорт | `cqa export --group DEV --format csv --out results.csv [--final]` |
| Журнал вызовов | `cqa log --last` · `cqa log --id N` |
| Чек-лист | `cqa checklist validate PATH` · `cqa checklist import PATH` · `cqa checklist show` |
| Сравнить разметки | `cqa compare eval/gold.csv eval/runs/….csv --traps --by language` |
| Сигналы | `cqa signals run --group DEV` · `cqa signals show` |
| Перекрёстная проверка | `cqa cross-check --group DEV --criteria 03,08` |
| Автотесты | `cqa autotest generate --per-mutation 15` · `cqa autotest run` · `cqa autotest report` |
| Операторы, срезы | `cqa operators [--name X]` · `cqa operators assign UID ИМЯ` · `cqa slices --by language` |
| Прецеденты | `cqa precedents list` · `cqa precedents to-version ID` · `cqa precedents similar ID` |
| Тренажёр | `cqa trainer start UID` · `cqa trainer reply ID "текст"` · `cqa trainer finish ID` |
| Тьютор, ассистент | `cqa tutor ask "вопрос" [--operator X]` · `cqa ask "вопрос"` |
| Заморозка | `cqa freeze` |
| Интерфейс | `cqa serve [--fake] [--dev]` · `cqa build-ui` · `cqa ui-preview` |

## 6. Контрольный этап (час 23)

```bash
uv run cqa freeze                                         # зафиксировать чек-лист и модель
uv run cqa load --group <CONTROL>                         # 10 новых диалогов
uv run cqa eval --group <CONTROL> --frozen                # около 1–4 мин, около $0.26
uv run cqa export --group <CONTROL> --format csv --out control.csv
```

Результаты вручную не правим — их сверяют с эталоном организаторов. Замену критерия жюри делаем по сценарию из раздела 4.
